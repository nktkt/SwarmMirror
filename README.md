# SwarmMirror

A next-generation **Swarm Intelligence Engine** that predicts anything by simulating high-fidelity digital worlds powered by multi-agent AI.

Upload seed materials (research reports, news articles, novels, financial data), describe what you want to predict, and SwarmMirror constructs a parallel digital world where thousands of autonomous agents — each with independent personalities, long-term memory, and behavioral logic — interact and evolve on simulated social media platforms. Observe emergent group dynamics from a "god's eye view," generate detailed predictive analysis reports, and chat with individual agents to explore alternative futures.

> **You provide:** seed documents + a natural language prediction goal
> **SwarmMirror returns:** a comprehensive prediction report + an interactive digital world you can explore

## Features

- **Knowledge Graph Construction** — Automatically extract entities and relationships from uploaded documents using LLM-powered ontology generation and Zep Cloud graph storage
- **Autonomous Agent Profiles** — Generate detailed agent personas (personality, MBTI, demographics, profession, interests, communication style) from graph entities via LLM, with person/organization distinction and Zep context enrichment
- **Dual-Platform Simulation** — Run parallel Twitter and Reddit simulations where agents autonomously post, comment, like, repost, follow, mute, and interact across multiple rounds
- **LLM-Driven Simulation Engine** — Native Rust simulation engine where each agent action is generated by LLM based on persona, current feed, and platform state — not hardcoded or random
- **Intelligent Report Generation** — ReACT-pattern Report Agent with advanced graph search tools (InsightForge, PanoramaSearch, QuickSearch) produces comprehensive, section-by-section markdown analysis reports with tool call tracking
- **Agent Interview System** — Interview individual agents, batch interview groups, or survey all agents with LLM-driven in-character responses
- **Interactive Chat** — Chat with the Report Agent for deeper analysis, or interview simulation agents to understand their perspectives and motivations
- **Real-time Monitoring** — Track simulation progress round by round, view agent action timelines, inspect per-agent statistics, and monitor platform state
- **D3.js Graph Visualization** — Interactive force-directed graph with zoom, pan, node filtering, entity type legend, edge labels, click-to-inspect detail panel, and simulation status indicators
- **Intelligent Config Generation** — LLM generates simulation parameters including time scheduling, agent activity levels, sentiment biases, influence weights, and seed posts — with rule-based fallbacks

## Workflow

1. **Upload & Analyze** — Upload documents (PDF/MD/TXT) and describe your prediction goal. The LLM generates an ontology with up to 10 entity types and 10 relationship types, including fallback types (Person, Organization) for comprehensive coverage.

2. **Build Knowledge Graph** — Text is chunked (configurable size/overlap), fed to Zep Cloud in batches, and processed into a knowledge graph with entities and relationships. Progress is tracked in real time.

3. **Generate Agent Profiles** — Entities are extracted and filtered from the graph. For each entity, the LLM generates a detailed social media persona: personality traits, MBTI type, demographics, profession, communication style, stance on the topic, and interested topics. Person and organization entities receive different prompt strategies. Profiles are saved in both Reddit (JSON) and Twitter (CSV) formats.

4. **Configure Simulation** — The LLM analyzes the scenario and generates simulation parameters: time scheduling (peak/off-peak hours), per-agent activity levels and sentiment biases, influence weights, seed posts to kickstart discussion, and platform-specific settings. Rule-based fallbacks ensure robustness.

5. **Run Simulation** — A native Rust simulation engine executes rounds where each agent's action is generated by the LLM based on their persona, the current platform feed, and available actions (CREATE_POST, LIKE, REPOST, COMMENT, FOLLOW, etc.). Platform state (posts, comments, likes, follows) is maintained in memory. Actions are logged per-round as JSONL. Pause/stop/resume is supported.

6. **Generate Report** — A ReACT-pattern Report Agent plans a report outline, then generates each section by iteratively calling graph search tools (InsightForge for deep multi-query analysis, PanoramaSearch for broad overview, QuickSearch for fast lookups). Each section requires 3-5 tool calls minimum. Structured logs and console output are saved for full transparency.

7. **Explore & Interact** — Chat with the Report Agent (which can call tools during conversation), interview individual simulation agents in-character, batch interview groups, or survey all agents simultaneously. Interview history is preserved.

## Quick Start

### Prerequisites

| Tool | Version | Check |
|------|---------|-------|
| **Rust** | Latest stable | `rustc --version` |
| **Bun** | 1.0+ | `bun --version` |
| **Node.js** | 18+ | `node -v` |

### 1. Configure Environment

```bash
cp .env.example .env
# Edit .env with your API keys
```

**Required environment variables:**

```env
# LLM API (any OpenAI-compatible endpoint)
LLM_API_KEY=your_api_key
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL_NAME=qwen-plus

# Zep Cloud (free tier available at https://app.getzep.com/)
ZEP_API_KEY=your_zep_api_key
```

**Optional:**

```env
# Faster/cheaper LLM for non-critical tasks
LLM_BOOST_API_KEY=your_api_key
LLM_BOOST_BASE_URL=your_base_url
LLM_BOOST_MODEL_NAME=your_model_name

# Simulation defaults
OASIS_DEFAULT_MAX_ROUNDS=10
REPORT_AGENT_MAX_TOOL_CALLS=5
REPORT_AGENT_TEMPERATURE=0.5
```

### 2. Install Dependencies

```bash
# Install frontend dependencies
cd frontend && bun install

# Build backend (downloads Rust crates automatically)
cd ../backend && cargo build
```

### 3. Start Development Server

```bash
# From project root — starts both frontend and backend concurrently
npm install   # first time only, installs concurrently
npm run dev
```

| Service | URL |
|---------|-----|
| Frontend | http://localhost:3000 |
| Backend API | http://localhost:5001 |
| Health Check | http://localhost:5001/health |

### Docker Deployment

```bash
cp .env.example .env
# Edit .env with your API keys

docker compose up -d
```

Ports `3000` (frontend) and `5001` (backend) are exposed. Upload data persists via the `./backend/uploads` volume mount.
